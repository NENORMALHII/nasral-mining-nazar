# ТЗ: админ-панель Epic Mining 2

Версия 1.0. Дата: 2026-11-12.

## 1. Назначение

Внутриигровая панель для модерации сервера и выдачи ресурсов.
Работает в Roblox-клиенте, вся логика на сервере.
Не веб-панель. Не Studio-плагин.

## 2. Допущения

1. Проект собирается Rojo. Добавляется `default.project.json`, если его нет.
2. ID предметов и узлов уже есть в игре. Панель берёт их из существующего каталога, новый каталог не создаётся.
3. Валюта игрока хранится в `leaderstats.Cash`. Если поле называется иначе, путь задаётся в `Config.lua`.
4. Хранилище банов — отдельный DataStore `AdminBans`, ключ `ban_<UserId>`.
5. Список админов задаётся вручную в `Config.lua`. Автовыдачи по владельцу игры нет.

## 3. Роли и права

| Уровень | Роль | Права |
|---|---|---|
| 0 | Игрок | нет доступа, GUI не создаётся |
| 1 | Moderator | kick, teleport, bring, heal, respawn, announce |
| 2 | Admin | всё уровня 1 + выдача/установка валюты, выдача предметов, спавн узлов, бан/разбан, события |
| 3 | Owner | всё уровня 2 + изменение ролей, просмотр логов, ручная правка DataStore |

Роль хранится по `UserId`, не по имени. Смена имени не должна менять права.

## 4. Функциональные требования

### 4.1 Игроки

- Список игроков: `UserId`, имя, роль, жив/мёртв, позиция, ping.
- Поиск по имени, регистронезависимый, без задержки на 50 игроках.
- `player.kick(userId, reason)` — reason обязателен, 3..200 символов.
- `player.ban(userId, reason, minutes)` — `minutes` 1..525600, `0` = навсегда.
- `player.unban(userId)` — только уровень 3.
- `player.teleportTo(userId)` — админ перемещается к игроку.
- `player.bring(userId)` — игрок перемещается к админу.
- `player.heal(userId)`, `player.respawn(userId)`.
- Действия над собой разрешены, кроме kick и ban.

### 4.2 Экономика

- `player.giveCash(userId, amount)` — `amount` целое, `-1e6..1e6`.
- `player.setCash(userId, amount)` — `0..1e12`, только уровень 2+.
- `inventory.giveItem(userId, itemId, count)` — `count` 1..10000.
- Баланс после операции не может быть отрицательным: сервер обрезает до 0 и возвращает фактическое значение.
- Все изменения пишутся в аудит с дельтой.

### 4.3 Мир

- `node.spawn(nodeTypeId, count)` — `count` 1..50, точка выбирается сервером в радиусе 50 studs от админа.
- `event.start(eventId, seconds)` — `seconds` 30..3600.
- `event.stop(eventId)`.
- `announce(text)` — 3..200 символов, не чаще 1 раза в 5 секунд на админа.

### 4.4 Диагностика

- `system.stats` — число игроков, uptime, версия панели.
- `system.logs(limit)` — последние N записей аудита, `limit` 1..500, только уровень 3.

## 5. Архитектура

```
ReplicatedStorage/AdminPanel/Protocol.lua      общие константы, коды ошибок
ServerScriptService/AdminPanel/init.server.lua точка входа, PlayerAdded, ban-check
ServerScriptService/AdminPanel/Config.lua      роли, лимиты, пути
ServerScriptService/AdminPanel/Permission.lua  проверка уровня
ServerScriptService/AdminPanel/RateLimit.lua   token bucket на игрока
ServerScriptService/AdminPanel/Audit.lua       буфер 500 записей
ServerScriptService/AdminPanel/Router.lua      разбор запроса, вызов команды
ServerScriptService/AdminPanel/Commands/*.lua  Players, Economy, World, System
StarterPlayer/StarterPlayerScripts/AdminPanelClient/init.client.lua
StarterPlayer/StarterPlayerScripts/AdminPanelClient/UI/*.lua
```

Правила:

1. Один RemoteFunction `AdminPanel.Invoke` в `ReplicatedStorage/AdminPanel`.
2. Один RemoteEvent `AdminPanel.Session` для выдачи роли клиенту и принудительного закрытия панели.
3. Команда — функция `run(ctx, args) -> ok, dataOrCode`. Регистрируется в таблице `Commands`.
4. Клиент не содержит списка команд. Клиент получает доступные команды от сервера при открытии.
5. Сторонние библиотеки не добавляются.

## 6. Протокол

Запрос:

```lua
Invoke({ command = "player.kick", args = { 123456, "afk" } })
```

Ответ:

```lua
{ ok = true,  data = { ... } }
{ ok = false, code = "ERR_RATE_LIMIT", message = "try later" }
```

Коды ошибок, все в `Protocol.lua`:

| Код | Когда |
|---|---|
| `ERR_NOT_ADMIN` | нет роли |
| `ERR_FORBIDDEN_LEVEL` | роль ниже требуемой |
| `ERR_UNKNOWN_COMMAND` | команда не зарегистрирована |
| `ERR_BAD_ARGS` | тип, длина или диапазон неверны |
| `ERR_TARGET_NOT_FOUND` | игрок офлайн или не существует |
| `ERR_RATE_LIMIT` | превышен лимит |
| `ERR_INTERNAL` | исключение внутри команды |

Требования:

1. Сервер не падает при любом входе: `pcall` вокруг `run`, ответ `ERR_INTERNAL`.
2. Аргументы проверяются по типу до вызова команды.
3. Лимит: 10 команд в секунду на админа, bucket на 20.
4. Клиент не передаёт и не влияет на свой уровень доступа.

## 7. Безопасность

1. Клиентский GUI — только UX. Любая команда повторно проверяется на сервере.
2. Роль выдаётся в `System.Session` только тем, у кого она есть в `Config`. Остальные получают пустой ответ.
3. Бан проверяется на `PlayerAdded` до выдачи персонажа. DataStore читается через `pcall` с 3 попытками.
4. Телепорт админа к игроку ограничен: цель должна быть жива, расстояние не проверяется, но координаты берутся с сервера.
5. Обязательно закрыть текущую дыру: `HarvestableNode.*.Interact.InteractEvent` сейчас принимает вызов от любого клиента. Сервер должен проверять дистанцию до узла (<= 8 studs), кулдаун на игрока (>= 0.5 с) и что узел не собран. Скрипт `mushrooms.lua`, который телепортирует персонажа и вызывает событие, после этого должен перестать давать ресурсы.
6. Запрещено: `loadstring`, выполнение кода, присланного клиентом, передача `Instance` в аргументах.

## 8. Аудит

Запись: `ts`, `adminId`, `adminName`, `command`, `args`, `ok`, `code`, `delta`.

1. Буфер в памяти на 500 записей.
2. `print` в серверный лог для каждой записи.
3. Опциональный webhook Discord, URL в `Config`. Если URL пуст, отправка пропускается.
4. Ошибка webhook не влияет на выполнение команды.

## 9. UI

1. Открытие по `F2`, клавиша в `Config`. Открытие только при роли >= 1.
2. Вкладки: Players, World, Logs. Logs видна только уровню 3.
3. Список игроков виртуализируется: не более 20 строк в кадре.
4. Опасные действия (kick, ban, setCash, unban) требуют подтверждения во втором окне.
5. Esc и повторный F2 закрывают панель.
6. Панель не блокирует управление персонажем, пока не открыто поле ввода.
7. Клиент показывает `message` из ответа сервера в нижней строке, без стектрейсов.

## 10. Нефункциональные требования

1. p95 выполнения команды <= 100 мс без учёта сетевых задержек.
2. Панель работает при 50 игроках на сервере.
3. Ноль ошибок в Output за 30 минут обычной игры без админ-действий.
4. Код Luau, стиль как в существующих файлах проекта, без глобальных переменных.

## 11. Критерии приёмки

1. Игрок без роли вызывает `AdminPanel.Invoke` вручную — получает `ERR_NOT_ADMIN`, никаких изменений в игре.
2. Moderator вызывает `player.giveCash` — `ERR_FORBIDDEN_LEVEL`.
3. 50 запросов за секунду — часть отклонена `ERR_RATE_LIMIT`, сервер жив.
4. `player.kick` с пустым reason — `ERR_BAD_ARGS`, игрок не кикнут.
5. Бан сохраняется после рестарта сервера, повторный вход блокируется.
6. `mushrooms.lua` запущен на клиенте — ресурсы не начисляются, в логе сервера запись об отклонённом Interact.
7. Каждая команда даёт запись в аудите с правильными `adminId` и `command`.
8. При выключенном webhook панель работает без ошибок.

## 12. Вне рамок

- Веб-дашборд, Telegram-бот.
- Автоматическая выдача ролей по группе Roblox.
- Откат действий (undo), версионирование инвентаря.
- Локализация, кроме русского текста интерфейса.
